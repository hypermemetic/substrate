# MCP Validation Guide

This document describes how to validate MCP (Model Context Protocol) compliance for Substrate using CLI-based tools.

## Available Tools

| Tool | Type | Protocol Versions | Best For |
|------|------|-------------------|----------|
| **mcp-validator** | Python CLI | 2024-11-05, 2025-03-26, 2025-06-18 | Comprehensive compliance testing |
| **MCP Inspector** | Node.js CLI/UI | All | Interactive debugging |

## mcp-validator (Primary)

The [mcp-validator](https://github.com/Janix-ai/mcp-validator) is a comprehensive test suite for validating MCP server implementations.

### Installation

```bash
cd /tmp
git clone https://github.com/Janix-ai/mcp-validator.git
cd mcp-validator
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

### STDIO Compliance Testing

For testing servers that communicate over stdio:

```bash
cd /tmp/mcp-validator
source .venv/bin/activate

# Basic compliance test
python -m mcp_testing.scripts.compliance_report \
  --server-command "/path/to/substrate --stdio --mcp" \
  --protocol-version 2025-03-26

# With debug output
python -m mcp_testing.scripts.compliance_report \
  --server-command "/path/to/substrate --stdio --mcp" \
  --protocol-version 2025-03-26 \
  --debug

# Tools-only testing (skip other features)
python -m mcp_testing.scripts.compliance_report \
  --server-command "/path/to/substrate --stdio --mcp" \
  --protocol-version 2025-03-26 \
  --test-mode tools \
  --dynamic-only

# Custom timeouts for slow operations
python -m mcp_testing.scripts.compliance_report \
  --server-command "/path/to/substrate --stdio --mcp" \
  --protocol-version 2025-03-26 \
  --test-timeout 60 \
  --tools-timeout 30
```

### HTTP Compliance Testing

For testing Streamable HTTP transport:

```bash
# Start substrate HTTP server first
/path/to/substrate --http --port 4444 --mcp &

# Run HTTP compliance tests
python -m mcp_testing.scripts.http_compliance_test \
  --server-url http://localhost:4444/mcp \
  --output-dir reports \
  --debug
```

### CLI Options Reference

| Option | Description | Example |
|--------|-------------|---------|
| `--server-command` | Command to spawn stdio server | `"substrate --stdio --mcp"` |
| `--server-url` | HTTP endpoint URL | `http://localhost:4444/mcp` |
| `--protocol-version` | MCP protocol version | `2025-03-26` |
| `--test-mode` | Focus on specific area | `tools` |
| `--dynamic-only` | Auto-discover tools | (flag) |
| `--test-timeout` | General timeout (seconds) | `30` |
| `--tools-timeout` | Tool-specific timeout | `15` |
| `--skip-tests` | Skip specific tests | `test1,test2` |
| `--required-tools` | Tools that must exist | `tool1,tool2` |
| `--skip-async` | Skip async tool tests | (flag) |
| `--output-dir` | Report output directory | `reports` |
| `--debug` | Verbose output | (flag) |

## MCP Inspector (Secondary)

The [MCP Inspector](https://github.com/modelcontextprotocol/inspector) is the official debugging tool.

### Installation

```bash
npm install -g @modelcontextprotocol/inspector
# or
npx @modelcontextprotocol/inspector
```

### CLI Mode

```bash
# List tools
npx @modelcontextprotocol/inspector --cli \
  /path/to/substrate --stdio --mcp \
  --method tools/list

# Call a tool
npx @modelcontextprotocol/inspector --cli \
  /path/to/substrate --stdio --mcp \
  --method tools/call \
  --params '{"name":"bash.execute","arguments":{"command":"ls"}}'

# Interactive mode (opens UI)
npx @modelcontextprotocol/inspector \
  /path/to/substrate --stdio --mcp
```

### UI Mode

For visual debugging:

```bash
npx @modelcontextprotocol/inspector /path/to/substrate --stdio --mcp
# Opens browser at http://localhost:5173
```

## Substrate Integration

### Validation Script

Create a validation script for CI:

```bash
#!/bin/bash
# scripts/validate-mcp.sh

set -e

SUBSTRATE_BIN="${1:-./target/release/substrate}"
PROTOCOL_VERSION="${2:-2025-03-26}"

cd /tmp/mcp-validator
source .venv/bin/activate

echo "=== MCP Compliance Test ==="
echo "Binary: $SUBSTRATE_BIN"
echo "Protocol: $PROTOCOL_VERSION"
echo ""

python -m mcp_testing.scripts.compliance_report \
  --server-command "$SUBSTRATE_BIN --stdio --mcp" \
  --protocol-version "$PROTOCOL_VERSION" \
  --output-dir reports \
  --debug

# Check exit code
if [ $? -eq 0 ]; then
  echo "✓ MCP Compliance: PASSED"
  exit 0
else
  echo "✗ MCP Compliance: FAILED"
  exit 1
fi
```

### Makefile Target

```makefile
# Makefile

.PHONY: mcp-validate

mcp-validate: build
	@echo "Validating MCP compliance..."
	@./scripts/validate-mcp.sh ./target/release/substrate 2025-03-26

mcp-validate-http: build
	@echo "Starting substrate HTTP server..."
	@./target/release/substrate --http --port 4444 --mcp &
	@sleep 2
	@cd /tmp/mcp-validator && source .venv/bin/activate && \
		python -m mcp_testing.scripts.http_compliance_test \
			--server-url http://localhost:4444/mcp \
			--output-dir reports
	@pkill -f "substrate --http"
```

### GitHub Actions

```yaml
# .github/workflows/mcp-compliance.yml

name: MCP Compliance

on:
  push:
    paths:
      - 'src/**'
      - 'Cargo.toml'

jobs:
  mcp-test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Build substrate
        run: cargo build --release

      - name: Setup mcp-validator
        run: |
          cd /tmp
          git clone https://github.com/Janix-ai/mcp-validator.git
          cd mcp-validator
          python3 -m venv .venv
          source .venv/bin/activate
          pip install -r requirements.txt

      - name: Run MCP compliance tests
        run: |
          cd /tmp/mcp-validator
          source .venv/bin/activate
          python -m mcp_testing.scripts.compliance_report \
            --server-command "${{ github.workspace }}/target/release/substrate --stdio --mcp" \
            --protocol-version 2025-03-26 \
            --output-dir reports

      - name: Upload report
        uses: actions/upload-artifact@v4
        with:
          name: mcp-compliance-report
          path: /tmp/mcp-validator/reports/
```

## Protocol Version Testing

Test against multiple protocol versions:

```bash
#!/bin/bash
# Test all supported versions

for version in "2024-11-05" "2025-03-26" "2025-06-18"; do
  echo "=== Testing $version ==="
  python -m mcp_testing.scripts.compliance_report \
    --server-command "substrate --stdio --mcp" \
    --protocol-version "$version" \
    --output-dir "reports/$version"
done
```

## Debugging Failed Tests

### Common Issues

| Error | Cause | Fix |
|-------|-------|-----|
| `Method not found: initialize` | MCP not implemented | Implement initialize handler |
| `Server not initialized` | Called method before init | Check state machine |
| `Invalid params` | Schema mismatch | Validate input schemas |
| `Timeout` | Server hung | Check async handling |
| `Connection refused` | Server not started | Check spawn command |

### Verbose Debugging

```bash
# Maximum verbosity
RUST_LOG=trace python -m mcp_testing.scripts.compliance_report \
  --server-command "substrate --stdio --mcp" \
  --protocol-version 2025-03-26 \
  --debug 2>&1 | tee mcp-debug.log
```

### Manual Testing

For manual protocol testing:

```bash
# Send raw JSON-RPC to substrate
echo '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-03-26","capabilities":{},"clientInfo":{"name":"test","version":"1.0"}}}' | \
  substrate --stdio --mcp

# Expected response:
# {"jsonrpc":"2.0","id":1,"result":{"protocolVersion":"2025-03-26","capabilities":{...},"serverInfo":{...}}}
```

## Compliance Checklist

Before running validation:

- [ ] `--mcp` flag implemented and enables MCP mode
- [ ] `initialize` method returns capabilities
- [ ] `notifications/initialized` transitions to Ready state
- [ ] `tools/list` returns all Plexus activations as MCP tools
- [ ] `tools/call` routes to Plexus and returns content
- [ ] Error responses use correct JSON-RPC error codes
- [ ] No embedded newlines in JSON output (stdio)
